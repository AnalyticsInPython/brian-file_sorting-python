     request/ 파일 날짜별 정리 스크립트

     Context

     request/ 폴더에 회사명과 날짜가 섞인 이름의 파일들(apple_20260212.xls,
     anthropic_20260213.csv, ...)이 평평하게 쌓여 있고, 이를 날짜별 디렉토리
     트리로 재배치해야 한다. 파일명에는 오타·대소문자 차이·확장자 불일치가 섞여
     있을 수 있고, 내용이 깨졌거나 확장자와 실제 포맷이 다른 파일도 있을 수
     있다.

     핵심 원칙은 스크립트가 추측해서 조용히 넘어가지 않는 것이다. 확실하게
     판정되는 파일만 자동 배치하고, 애매한 것은 격리 폴더로 보내 사람이
     판단하도록 리포트한다. 잘못 정리된 파일은 잘못 정리됐다는 사실조차 드러나지
     않기 때문에, "틀리게 정리"보다 "정리하지 않고 보고"가 항상 낫다.

     작업 디렉토리에 아직 아무 파일도 없으므로, 테스트용 픽스처 생성기도 함께
     만든다.

     ---

     결정 사항 (확정)

     ┌───────────┬───────────────────────────────────────────────────────┐
     │   항목    │                         결정                          │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 출력 구조 │ request_by_date/YYYY/MM/DD/파일명                     │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 기본 동작 │ dry-run (--apply 시 실제 이동, --copy 시 복사)        │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 파싱 실패 │ _unresolved/ 격리 + 리포트. 자동 추측·mtime 대체 없음 │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 무결성    │ 매직바이트로 실제 포맷 판별, 확장자 불일치 리포트     │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 파일명    │ 원본 유지. 유사 이름 클러스터만 리포트                │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 이름 충돌 │ SHA-256 비교 → 동일하면 중복 처리, 다르면 __2 접미사  │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 탐색      │ request/ 하위 재귀                                    │
     ├───────────┼───────────────────────────────────────────────────────┤
     │ 날짜 패턴 │ YYYY[구분자]MM[구분자]DD 만. 모호한 것은 격리         │
     └───────────┴───────────────────────────────────────────────────────┘

     산출물

     - sort_requests.py — 메인 스크립트. 표준 라이브러리만 사용 (현재 환경에
       pandas/openpyxl 미설치, Python 3.14.7)
     - make_fixtures.py — 모든 엣지 케이스를 담은 테스트용 request/ 생성기

     ---

     CLI

     python3 sort_requests.py [SRC] [-o DEST] [--apply] [--copy]
                              [--report PATH] [--manifest PATH]
                              [--undo MANIFEST]

     - SRC 기본값 request, DEST 기본값 request_by_date
     - 플래그 없이 실행 = dry-run. 아무것도 건드리지 않고 계획과 리포트만 출력
     - --apply = 실제 이동, --apply --copy = 원본 보존 복사
     - --undo MANIFEST = manifest 기록을 역순으로 되돌림

     ---

     처리 파이프라인

     1단계: 수집 (Collect)

     os.walk로 SRC 재귀 탐색.

     제외 대상 (리포트에 skipped로 기록):
     - macOS 부산물: .DS_Store, ._* (AppleDouble), .Spotlight-V100, .Trashes,
       .fseventsd
     - Windows 부산물: Thumbs.db, desktop.ini
     - 오피스 임시 잠금 파일: ~$*
     - 심볼릭 링크 (끊긴 링크 포함) — 따라가지 않고 별도 보고
     - DEST가 SRC 안에 있는 경우 그 하위 전체 (재실행 시 자기 결과물을 다시 먹는
       사고 방지)

     macOS 유니코드 주의: APFS/HFS+는 파일명을 NFD로 반환한다. 비교·중복
     판정·유사 이름 그룹핑에는 항상 unicodedata.normalize("NFC", name) 를
     적용하고, 실제 파일 접근에는 원본 문자열을 쓴다.

     2단계: 날짜 파싱

     파일명 stem(확장자 제외)에 대해:

     DATE_RE = re.compile(r"(?<!\d)(\d{4})[-_.\s]?(\d{2})[-_.\s]?(\d{2})(?!\d)")

     판정 규칙:
     1. 매치 0개 → NO_DATE → 격리
     2. 매치 2개 이상이고 서로 다른 날짜 → AMBIGUOUS_MULTI_DATE → 격리 (같은
        날짜 반복은 통과)
     3. 연도가 1990 ≤ y ≤ 2100 범위 밖 → YEAR_OUT_OF_RANGE → 격리 (20261340 류
        오탐 차단)
     4. datetime.date(y, m, d) 가 ValueError → INVALID_DATE → 격리 (20260230,
        20261340)
     5. 통과 → 목적지 확정

     명시적으로 인식하지 않는 것 (전부 격리):
     - 02122026 — MMDDYYYY인지 DDMMYYYY인지 판별 불가
     - 260212 — 2자리 연도, 모호
     - Feb 12 2026 같은 영문 월 표기 — 필요하면 나중에 추가

     3단계: 포맷 검증 (매직바이트)

     파일 앞 512바이트를 읽어 실제 포맷을 판별:

     ┌───────────────────────────────┬─────────────────────────────────────────┐
     │           시그니처            │                  판정                   │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ D0 CF 11 E0 A1 B1 1A E1       │ OLE2 (레거시 .xls/.doc)                 │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ 50 4B 03 04                   │ ZIP 컨테이너 (.xlsx/.docx, 또는 순수    │
     │                               │ zip)                                    │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ %PDF-                         │ PDF                                     │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ <?xml / <html / <table        │ HTML/XML — "엑셀에서 내보낸 .xls"의     │
     │ (공백·BOM 무시, 대소문자      │ 흔한 실체                               │
     │ 무시)                         │                                         │
     ├───────────────────────────────┼─────────────────────────────────────────┤
     │ 그 외                         │ 텍스트 후보. UTF-8 / UTF-8-BOM / CP949  │
     │                               │ / Latin-1 순으로 샘플 디코딩 시도       │
     └───────────────────────────────┴─────────────────────────────────────────┘

     확장자와 실제 포맷이 어긋나면 EXT_MISMATCH로 리포트만 하고 배치는 정상
     진행한다 (날짜는 파일명에서 이미 확실히 읽었으므로 격리할 이유가 없음).

     다만 아래는 실질적으로 깨진 파일이므로 격리한다:
     - 0바이트 파일 → EMPTY_FILE
     - PermissionError / OSError로 열리지 않음 → UNREADABLE

     4단계: 배치 계획 수립

     목적지: DEST/YYYY/MM/DD/원본파일명

     충돌 처리 — macOS 기본 파일시스템은 대소문자 구분 안 함이므로, 충돌 판정
     키는 반드시 NFC 정규화 + casefold() 로 만든다. Python이 보기엔 다른
     이름이어도 OS에선 같은 파일로 덮어써지기 때문이다.

     1. 충돌 없음 → 그대로 배치
     2. 충돌 + SHA-256 동일 → DUPLICATE. 첫 번째만 날짜 폴더에 두고, 나머지는
        DEST/_duplicates/YYYY-MM-DD/ 로 이동 + 리포트
        - 삭제하지 않는다. 사용자가 리포트를 확인한 뒤 _duplicates/ 를 통째로
          지우는 게 안전
     3. 충돌 + 해시 다름 → NAME_COLLISION. stem__2.ext, stem__3.ext 순으로
        접미사를 붙여 둘 다 보존 + 리포트

     해시는 충돌이 실제로 발생한 파일에 대해서만 계산한다 (전체 해싱은 불필요한
     I/O).

     5단계: 실행

     dry-run이면 계획 테이블만 출력하고 종료. --apply 일 때:

     - os.makedirs(dest_dir, exist_ok=True)
     - 이동은 shutil.move, 복사는 shutil.copy2 (mtime 보존)
     - 파일 단위 try/except — 한 파일이 실패해도 전체가 중단되지 않고 ERROR로
       기록 후 계속
     - Write-ahead manifest: 각 파일을 옮기기 직전에 JSONL 한 줄을 쓰고 flush()
       + os.fsync(). 실행 중 크래시나 Ctrl-C가 나도 그 시점까지의 이동이 전부
       undo 가능
     - SIGINT 핸들러로 Ctrl-C 시 현재 파일 처리를 마치고 깔끔히 종료

     6단계: 리포트

     stdout 요약
     스캔 152개 | 배치 138 | 격리 9 | 중복 3 | 이름충돌 1 | 스킵 1
     확장자 불일치 7건 — 리포트 참고
     유사 파일명 클러스터 2건 — 확인 필요

     sort_report.csv (컬럼): status, source_path, dest_path, parsed_date, ext,
     detected_format, size, reason

     유사 파일명 리포트 — 사용자가 언급한 오타·대소문자 케이스를 잡되, 이름은 
     절대 바꾸지 않는다:
     1. 각 파일명 stem에서 날짜·구분자·숫자를 제거해 "회사명 토큰"만 추출
     2. NFC 정규화 + casefold 후, difflib.SequenceMatcher 유사도 ≥ 0.85 로
        클러스터링
     3. 한 클러스터 안에 서로 다른 철자가 2개 이상이면 출력

     [SIMILAR NAMES] — 같은 회사의 오타/표기 차이일 수 있습니다
       anthropic   (2 files)  20260213, 20260220
       Anthropic   (1 file)   20260214
       anthropicc  (1 file)   20260218   <- 편집거리 1

     파일 배치는 날짜만으로 결정되므로 이 리포트는 정보 제공용이다. 사용자가
     보고 판단해서 원본을 고치면 재실행하면 된다.

     7단계: Undo

     --undo sort_manifest.jsonl → manifest를 역순으로 읽어 각 이동을 되돌린다.
     목적지 파일이 이미 없거나 원본 자리에 다른 파일이 생겼으면 건너뛰고 보고.
     되돌린 뒤 빈 디렉토리는 정리한다.

     스크립트 구조 (sort_requests.py)

     main()                    argparse, 오케스트레이션
     ├─ collect_files()        재귀 walk + 제외 규칙
     ├─ parse_date()           정규식 + 유효성 검사 → (date | None, reason)
     ├─ detect_format()        매직바이트 → 포맷 문자열
     ├─ plan_moves()           목적지 계산, 충돌/중복 판정 (해시는 필요할 때만)
     ├─ execute()              dry-run 분기, write-ahead manifest, per-file
     try/except
     ├─ find_similar_names()   difflib 기반 클러스터링
     ├─ write_report()         CSV + stdout 요약
     └─ undo()                 manifest 역재생

     각 함수는 순수 함수에 가깝게 유지해 개별 테스트가 가능하도록 한다. 전역
     상태 없음.
